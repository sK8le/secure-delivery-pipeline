# Как принимается решение по DAST

ZAP запускается против временного kind-кластера с тем же контейнерным образом, который прошёл Trivy. Активное сканирование применяется только к этому одноразовому стенду.

1. Скрипт HTTP-проверки подтверждает изоляцию команд на PostgreSQL.
   Отдельный запрос с именем длиннее 64 символов должен получить HTTP 422: это регрессия ошибки регистрации, найденной ZAP.
2. Создаётся отдельный пользователь сканера, оператор назначает ему отдельную команду.
3. `dast_target.py` импортирует контрольную запись. До и после скана проверяются восемь маршрутов: состояние приложения, регистрация, вход, список, поиск, карточка, импорт и калькулятор CVSS. Защищённые страницы должны содержать ожидаемые данные, без перенаправления на вход.
4. Hook добавляет эти адреса в дерево ZAP, а перед завершением собирает сведения из истории самого сканера: достигнутые адреса, ответы 5xx и состояние активного и пассивного анализа.
5. `dast_gate.py` сопоставляет отчёт ZAP с проверками стенда и политикой `.zap/rules.tsv`.

## Три результата

| Решение | Значение | Поставка |
|---|---|---|
| `passed` | Скан завершён, обязательные страницы достигнуты, блокирующих находок нет | Допущена проверками |
| `blocked` | Любая находка High или правило с действием FAIL | Запрещена |
| `scan_error` | Нет/повреждён отчёт, HTTP 5xx, потеря доступа или неполный скан | Запрещена |

Любой High блокирует независимо от идентификатора правила и записи WARN/IGNORE в TSV. SQL Injection 40018 дополнительно задан как FAIL. Отсутствие находок при отказе сканера не считается успешной проверкой.

Исключения стенда: Secure/HSTS предупреждают из-за HTTP без TLS; отсутствие CSRF-токенов остаётся явным техническим долгом. Успешный DAST не доказывает отсутствие всех уязвимостей и не заменяет проверку прав доступа с несколькими пользователями.

## Артефакты запуска

`test-results` содержит JUnit всех тестов. `runtime-access-report` — условия проверки доступа через HTTP и PostgreSQL. `dast-evidence` содержит JSON/HTML ZAP, контрольные проверки до/после, наблюдение hook, идентификатор образа сканера и итоговое `gate.json`. При раннем отказе часть файлов может отсутствовать; итог остаётся `scan_error`.

```bash
python scripts/dast_gate.py --directory dast-reports --rules .zap/rules.tsv --output dast-reports/gate.json
```

Unit-тесты политики используют искусственные отчёты, включая High и SQLi. Они проверяют решение допуска, но сами по себе не доказывают, что настоящий ZAP обнаружил внедрённую SQL-инъекцию. Такое подтверждение требует отдельного контролируемого эксперимента и сохранённого отчёта сканера.

API сканера слушает только локальный интерфейс; список разрешает loopback и служебные имена `zap`/`localhost`. Исходный код подключается только для чтения, запись разрешена в отдельный каталог отчётов.
