# Назначение команд и изоляция данных

Регистрация создаёт пользователя без команды. Войти можно, но запросы к списку, поиску, карточкам, импорту и калькулятору возвращают HTTP 403 до назначения команды. Поле `team` из запроса регистрации игнорируется. Веб-маршрута назначения команды нет.

Оператор с доступом к контейнеру назначает команду:

```bash
kubectl -n vulntrack exec deployment/vulntrack-web -- python -m app.manage list-users
kubectl -n vulntrack exec deployment/vulntrack-web -- python -m app.manage assign-team --username alice --team blue
```

Права берутся из БД при каждом запросе, поэтому перенос пользователя в другую команду сразу прекращает доступ к предыдущей команде, в том числе с действующей сессией. Чужая карточка возвращает HTTP 404. При импорте команда актива и автор записи определяются сервером.

## Проверка

```bash
pytest tests/security/test_access_control.py tests/security/test_team_assignment.py -v
kubectl -n vulntrack exec -i deployment/vulntrack-web -- python - < scripts/check_runtime_access.py
```

Первый набор использует изолированную SQLite и проверяет регистрацию, выборку данных, импорт и изменение назначения. Второй выполняется внутри приложения против его HTTP-интерфейса и рабочей БД: создаёт временные учётные записи двух команд, проверяет 20 условий и удаляет свои данные. Он изменяет тестовые данные на стенде; запускать на тестовом окружении. Нужны все `passed: true`, `cleanup_ok: true` и `failure: null`.

Существующие учётные записи сохраняют прежние команды при обновлении. Оператор должен проверить список пользователей и исправить недоверенные назначения. Автоматическое переназначение существующих аккаунтов не выполняется.
